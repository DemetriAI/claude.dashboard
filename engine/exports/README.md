# exports/ — lead CSVs + the daily 8am email

Two files, regenerated by `engine/tools/build_exports.py` (auto-picks up any vertical that has a
`leads.csv`):

| File | What it is |
|---|---|
| `all_leads.csv` | Every target across all verticals (PROCEED + HALT) with a `vertical` column. |
| `ghl_contacts.csv` | **PROCEED leads only**, columns mapped for a **GoHighLevel** contact import. |

Regenerate anytime: `python3 engine/tools/build_exports.py`

---

## 📧 Daily email at 8:00am Central (GitHub Actions)

`.github/workflows/daily-leads-email.yml` rebuilds the CSVs and emails them to
**contact@premierconnectai.com** every morning at **08:00 America/Chicago** (DST-safe: it fires at
13:00 + 14:00 UTC and only the one that equals 8am Chicago actually sends).

### Turn it on (one time, ~2 minutes)
1. **Add two repo secrets** — GitHub → repo **Settings → Secrets and variables → Actions → New secret**:
   - `MAIL_USERNAME` = `contact@premierconnectai.com`
   - `MAIL_PASSWORD` = a **Google App Password** (Google Account → Security → 2-Step Verification →
     App passwords). Use an App Password, **not** your normal account password.
2. **Put this workflow on the default branch.** GitHub only runs *scheduled* workflows from the
   default branch, so merge this branch (or just this workflow) into it. Until then it won't fire.

### Test it immediately
After step 1+2: GitHub → **Actions → Daily leads email → Run workflow** (the manual `workflow_dispatch`
trigger ignores the time gate and sends right away).

> Prefer SendGrid/Mailgun, or a no-secrets path using your already-connected Gmail via a Claude Code
> scheduled trigger? Both are easy swaps — say which and I'll reconfigure.

- **Now (no credentials):** in GHL, **Contacts → Import**, upload `ghl_contacts.csv`, and map the
  columns (Business Name, Website, Tags, and the rest as custom fields). Tags arrive as
  `PremierConnect;<vertical>;<metro>` so you can build smart lists + automations per vertical.
- **Auto-sync (optional):** drop a GHL **Private Integration Token** into a repo secret and I'll add a
  step to this workflow that upserts the PROCEED contacts into GHL via the API v2 every morning — no
  manual import.

> Heads-up: contact PII (emails/phones) was deliberately kept out of the engine, so GHL contacts import
